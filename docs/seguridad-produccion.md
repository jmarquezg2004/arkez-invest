# Seguridad y preparación para producción

Auditoría local del 20 de noviembre de 2026. El sitio consta de 20 rutas públicas, recursos estáticos, una demostración de contacto por loopback y un adaptador de captación independiente para Cloudflare Workers. La compilación web mantiene la experiencia aprobada.

| Prioridad | Riesgo | Control implementado y alcance |
|---|---|---|
| Alta | XSS y scripts de terceros | CSP de origen propio con hashes SHA-256 recalculados para cada HTML exportado. Bloquea scripts inline sin hash, manejadores inline, eval, plugins, cambios de URL base y carga en marcos. JSON-LD serializa contenido del repositorio y escapa el carácter que inicia una etiqueta. Los enlaces a fuentes externas son navegación explícita. |
| Alta | Captación prematura, spam y datos personales | La página conserva la prueba local. El Worker separado viene desactivado, carece de ruta pública configurada y responde con error si faltan dependencias. Verifica origen y método, límite de 8 KiB, campos permitidos, trampa, aviso aceptado y Turnstile con hostname y acción. El límite es de cinco solicitudes por minuto por clave HMAC derivada de la IP de Cloudflare, por ubicación de red. La integración usa texto plano y destinos fijos del servidor. |
| Alta | Secretos en código, bundles o artefactos | La revisión por patrones abarcó código, exportación y blobs de las referencias Git locales. No aparecieron coincidencias con los patrones comprobados. Se revisaron las variables que llegan al frontend. Los secretos del futuro receptor se referencian únicamente en el Worker. La búsqueda por patrones no garantiza detectar secretos de formato desconocido. |
| Media | Clickjacking, contenido interpretado con MIME incorrecto y degradación HTTPS | Cloudflare Pages recibe `X-Frame-Options: DENY`, `frame-ancestors 'none'`, `nosniff`, política de referencia y permisos. El perfil de producción declara HSTS durante un año para el dominio canónico. Se requiere TLS válido antes de publicar. El Worker aplica cabeceras a sus propias respuestas. |
| Media | Indexación del entorno equivocado | Los perfiles local y de prueba usan `noindex, nofollow`. La compilación de producción habilita rastreo y mantiene las 20 canónicas. El artefacto de producción aplica un encabezado `noindex` a los hosts de Pages y sus alias. El acceso privado de las previsualizaciones se configura en el alojamiento. |
| Media | Dependencias, builds inconsistentes y cambios sin reversión | Node fijado, instalación con lockfile, auditoría npm, pruebas para los dos perfiles, archivo versionado por commit y suma SHA-256. El flujo CI sólo verifica y opera con permisos de lectura. |
| Alta pendiente | Interrupción del correo al cambiar de DNS | Confirmar proveedor, respaldo de zona, MX, SPF, DKIM, DMARC y verificaciones. Mantener el servicio de correo actual durante la migración web. Validar correo entrante y saliente antes y después del cambio. |

El limitador de Workers es por ubicación de Cloudflare. Para tráfico distribuido, definir el límite global y las alertas antes de habilitar captación. El Worker envía al proveedor de correo nombre, correo, servicio y mensaje sólo cuando se habilita el flujo autorizado. El cuerpo de la solicitud y la IP no se registran en la aplicación. El proveedor de correo y el buzón receptor requieren una política de acceso y retención. La validación con Turnstile procesa el token sin incluir la IP del visitante en la llamada de servidor. [Rate limiting de Workers](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/) · [Validación de Turnstile](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/) · [API de Resend](https://resend.com/docs/api-reference/emails/send-email)

## Alojamiento y costos

| Alternativa | Seguridad y operación | Dominio, DNS, correo y costos |
|---|---|---|
| Alojamiento existente, compatible con GitHub Pages según `CNAME` | La portada pública rastreada sigue mostrando la versión anterior. El CNAME y el repositorio son coherentes con GitHub Pages. El panel de alojamiento, las cabeceras, TLS y DNS efectivo no pudieron confirmarse desde el entorno de auditoría. GitHub Pages es estático y su publicación directa no aplica la configuración `_headers` de Cloudflare Pages. | Mantenerlo durante la comparación preserva el servicio actual. Confirmar el plan y la idoneidad de sus términos para un sitio corporativo comercial antes de elegirlo como destino. |
| Cloudflare Pages con artefacto estático | Permite cabeceras por ruta, HTTPS, previsualizaciones y reversión a un despliegue previo de producción. El Worker de contacto se administra por separado y puede quedar fuera del lanzamiento inicial. | Las solicitudes a activos estáticos se ofrecen sin costo según la documentación. El dominio raíz requiere la zona y nameservers en Cloudflare. Un subdominio de homologación puede usar CNAME con el DNS actual. Workers Free tiene cuotas. Workers Paid parte de US$5 al mes y el correo transaccional se cotiza por separado. Conservar contrato y configuración del correo corporativo. |

Se recomienda Pages estático con aprobación separada del contacto. La primera homologación se puede hacer sin trasladar la zona raíz. El dominio público y `main` permanecieron intactos. ## Evidencia local

- `npm audit` reportó cero vulnerabilidades en las dependencias resueltas por el lockfile. El resultado corresponde al catálogo consultado durante esta auditoría.
- 17 pruebas automatizadas abarcan las 20 canónicas, sitemap, robots, Schema.org, cabeceras y hashes, validación, origen, trampa, límites, expiración y respuestas simuladas del proveedor.
- Chromium recorrió las 20 rutas en siete anchos sin desbordamiento. Las comprobaciones axe-core A/AA evaluadas no reportaron infracciones. Se probó teclado, foco, menú móvil, FAQ, enlaces de servicios y la solicitud técnica local.
- En Chromium local a 390 px, con un contexto nuevo por ruta, LCP mediano de 164 ms y máximo de 256 ms, CLS máximo de 0,062 y 10–12 peticiones. Las rutas transfirieron aproximadamente 582–608 kB sin compresión usando loopback, sin solicitudes a otros orígenes. Son mediciones de laboratorio, sin CDN, latencia real ni datos de campo. Verificar LCP, INP y CLS de campo después de una publicación autorizada.
- Los controles de Pages se probaron localmente contra el export y las reglas generadas. Queda pendiente confirmar que Cloudflare entregue las cabeceras, TLS, robots y redirecciones en el dominio real. Las respuestas de Turnstile y Resend se probaron con dobles locales y datos ficticios.
